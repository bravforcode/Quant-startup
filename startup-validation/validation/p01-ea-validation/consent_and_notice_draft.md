# ร่างการขอความยินยอมและประกาศความเป็นส่วนตัว — P01

> **สถานะ: ร่าง ยังไม่ใช้.** ต้องให้ทนายตรวจก่อน (`stage3_protocol.md` §6 ข้อ 6) และผู้ก่อตั้งกรอกช่องในวงเล็บ `[ ]` ทั้งหมด
> ใช้เฉพาะกับผู้ที่ตอบรับเองหรือสมัครผ่านฟอร์ม opt-in เท่านั้น ไม่ใช้กับรายชื่อที่เก็บจากเว็บหรือกลุ่ม

## 1. หลักการที่ใช้กับทุกช่องทางอีเมล

1. ส่งเฉพาะคนที่ให้ความยินยอมแล้ว: ตอบรับเองในการสนทนา หรือกรอกฟอร์ม `waitlist_signups` ด้วยตัวเอง
2. ห้ามใช้อีเมลที่เก็บจากเว็บ กลุ่ม โปรไฟล์ หรือรายการที่ซื้อมา (`stage3_protocol.md` §11)
3. บันทึก consent record ทุกราย (ดูข้อ 4) และตั้ง `contacts.consent_recorded = true` เฉพาะเมื่อมีบันทึกแล้ว
4. ทุกฉบับมีลิงก์ยกเลิก และการยกเลิกต้องมีผลก่อนส่งฉบับถัดไป
5. ไม่ส่งข้อมูลติดต่อของคนหนึ่งให้บุคคลที่สาม
6. ก่อนส่งทุกชุด ผู้ก่อตั้งต้องยืนยันรายชื่อผู้รับและเนื้อความ

## 2. ข้อความขอความยินยอม (เช็กบ็อกซ์ ไม่ติ๊กไว้ล่วงหน้า)

> ☐ ฉันยินยอมให้ [ชื่อผู้ให้บริการ] เก็บอีเมลและข้อความที่ฉันพิมพ์ เพื่อติดต่อเรื่องการทดสอบบริการตรวจความทนทานของกลยุทธ์ EA ฉันเข้าใจว่าสามารถยกเลิกได้ทุกเมื่อ และการยกเลิกไม่กระทบสิทธิ์อื่นของฉัน
> รายละเอียดการเก็บและการใช้ข้อมูลอยู่ในประกาศความเป็นส่วนตัวด้านล่าง

## 3. ประกาศความเป็นส่วนตัว (ฉบับย่อ)

- **ผู้ควบคุมข้อมูล:** [ชื่อผู้ก่อตั้ง / ชื่อกิจการ] · [ที่อยู่] · [อีเมลติดต่อ]
- **ข้อมูลที่เก็บ:** อีเมล · ชื่อเล่น (ถ้ามี) · ข้อความที่ตอบ · คำตอบ screener 5 ข้อ · ช่องทางที่สมัคร
- **ข้อมูลที่ไม่เก็บ:** เลขบัญชีเทรด รหัสผ่าน หรือไฟล์ผลทดสอบ จนกว่าลูกค้าจะส่งเองในขั้นบริการจริง
- **วัตถุประสงค์:** ติดต่อเพื่อสัมภาษณ์หรือแจ้งความคืบหน้าของบริการที่กำลังทดสอบ
- **ฐานการใช้:** ความยินยอมของเจ้าของข้อมูล ซึ่งเจ้าของถอนได้ทุกเมื่อ
- **ระยะเวลาเก็บ:** [ระบุ เช่น จนกว่าจะถอนความยินยอม หรือ X เดือนหลังการทดสอบจบ]
- **ผู้รับข้อมูล:** ผู้ให้บริการเทคโนโลยีที่ใช้เก็บและส่งอีเมล ([ระบุชื่อบริการ] — ทนายต้องยืนยันว่าต้องระบุชื่อหรือไม่)
- **สิทธิของเจ้าของข้อมูล:** ขอเข้าถึง ขอแก้ไข ขอลบ ถอนความยินยอม และร้องเรียนต่อผู้มีอำนาจกำกับ — ติดต่อ [อีเมล]
- **ไม่ใช่คำแนะนำการลงทุน:** บริการที่กำลังทดสอบเป็นการวิเคราะห์ผลทดสอบที่ลูกค้าส่งมาเอง ไม่ได้แนะนำให้ซื้อหรือขาย และยังไม่เก็บเงินในขั้นนี้

## 4. บันทึกความยินยอม (consent record)

ทุกรายต้องมีค่าเหล่านี้ เก็บแยกจากข้อมูลติดต่อ:

| ฟิลด์ | ตัวอย่าง |
|---|---|
| alias | `p01-017` (ไม่ใช่ชื่อจริง) |
| วันที่ให้ความยินยอม | 2026-MM-DD |
| ช่องทาง | `waitlist_form` / `dm_reply` / `email_reply` |
| เวอร์ชันข้อความที่แสดง | `consent-v0.1-draft` (เปลี่ยนเวอร์ชันทุกครั้งที่แก้ถ้อยคำ) |
| วันที่ถอนความยินยอม | ว่างจนกว่าจะถอน |
| ผู้บันทึก | ผู้ก่อตั้ง |

**ข้อเสนอแนะ (ยังไม่ได้ทำ):** `sql/01_evidence_ledger.sql` มีแค่คอลัมน์ `consent_recorded` ในตาราง `contacts` ควรเพิ่มตาราง consent log แยกที่เก็บเวอร์ชันข้อความและวันถอนได้ แต่เป็นการเปลี่ยน schema จึงต้องรอให้ผู้ก่อตั้งเลือกโปรเจกต์ Supabase ก่อน

## 6. ข้อห้ามที่ต้องตรวจก่อนส่งทุกฉบับ

- ไม่มีคำว่า "จำกัด 50 คนแรก" ถ้าไม่ได้จำกัดจริง (แพลนข้อ 7)
- ไม่อ้างว่าเป็นงานวิจัยของมหาวิทยาลัย ถ้าไม่ใช่งานวิจัยจริง (แพลนข้อ 11)
- ไม่มีลิงก์ยกเลิก = ไม่ส่ง
- ไม่มีบันทึกความยินยอม = ไม่ส่ง
